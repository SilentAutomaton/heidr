# Тестирование

Цель у набора тестов одна: у каждого поведения есть ровно одна проверка, которая
падает, когда это поведение сломалось. Покрытие мы измеряем, но не гонимся за
ним. Набор, который повторяет код построчно, ничего не проверяет по существу и
только мешает этот код менять.

## Как запускать

```
pytest                  # всё, чему не нужны железо и сеть
pytest -m live          # остальное: настоящий эфир, сеть, звуковое устройство
```

Тесты с пометкой `live` исключены по умолчанию — это прописано в
`pyproject.toml`. Обычный прогон должен проходить на любой машине, где есть
только Python.

## Набор, который растёт сам

Файл `tests/test_registry_contract.py` параметризован по всем зарегистрированным
модулям сразу. Появился новый модуль — он автоматически попал под все проверки, и
писать для него отдельный файл не нужно.

Проверяется вот что: возвращаемый тип соответствует обещанию слота; `available()`
возвращает булево значение и никогда не бросает исключений; объявленные
потребности состоят из известных имён; модуль переживает пустой вопрос и
подставной контекст; документация есть на обоих языках, и в ней на месте разделы
о зависимостях и источниках.

Из-за этого большинству модулей собственные тесты не нужны вовсе. Отдельный тест
пишется только на ту логику, которую контрактная проверка увидеть не может.

## Что получает свой тест

По одной проверке на каждое поведение, которое действительно может сломаться:

- обряд вопроса детерминирован, то есть один и тот же вопрос даёт один и тот же
  ключ;
- счёт по методу Да Янь даёт настоящее распределение, где старые линии выпадают
  заметно реже молодых, — проверяется статистически на большом числе бросков с
  допуском;
- дебиасинг фон Неймана убирает смещение из заведомо смещённого потока;
- биекция Вавилонской библиотеки обратима: адрес превращается в текст, а текст
  восстанавливает адрес;
- цепочка журнала сходится, а подделанная запись обнаруживается;
- повторно заданный вопрос отклоняется;
- штраф за недавнее использование снижает вес модуля, но не обнуляет его;
- слои настроек перекрываются в правильном порядке, а запись обратно сохраняет
  только то, что отличается от значений по умолчанию;
- определение возможностей терминала даёт ожидаемые уровни на матрице значений
  `TERM` и `COLORTERM`;
- регулировка усиления выводит сигнал на целевой уровень, а ограничитель ни разу
  не превышает потолок;
- каждый разборщик сетевого ответа справляется со своим записанным образцом.

## Что тестами не покрывается

Тривиальные обёртки, конструирование дата-классов, таблица строк, внутренности
Textual, точные формулировки сообщений и форматирование вывода.

Проще всего запомнить так: **если тест ломается от переименования переменной,
такого теста быть не должно.**

## Границы

Тесты не трогают ни сеть, ни радио, ни звуковую карту — иначе они перестают быть
воспроизводимыми. Вместо настоящих источников в `tests/conftest.py` лежат
подставные.

| Подставка | Что заменяет |
|---|---|
| `stub_context` | настоящий `Context`, шина событий работает в памяти |
| `fake_pcm` | `rtl_fm`, выдаёт синтетические отсчёты |
| `fake_llm` | любого поставщика модели, выдаёт заданный список токенов |
| `fake_stt` | любое распознавание речи, выдаёт заданный текст |
| `tests/fixtures/*.json` | записанные ответы USGS, blockchain, маяка и ADS-B |

Если тесту действительно нужно настоящее железо или живая сеть, он помечается и
в обычный прогон не попадает:

```python
@pytest.mark.live
def test_dongle_actually_tunes(): ...
```

## Тесты интерфейса

Интерфейс водит штатный `App.run_test()` из Textual. Проверяем поведение и
принятое решение о раскладке, но не пиксели: переходы между режимами, разбор
команд, отказ на слишком маленьком терминале, перестроение при изменении размера
от 40×12 до 200×50, переопределение клавиш из конфига и откат к более простой
визуализации, когда глифов не хватает.

Снимков экрана мы не делаем. Они ломаются от любой посторонней правки и ничему
при этом не учат.

## Где живут тесты

В том же коммите, что и код, который они покрывают. Отдельного шага «а теперь
напишем тесты» в конце плана нет и не будет: он всегда означает, что тестов не
будет вообще.
