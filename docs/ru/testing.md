# Тесты

[HEID//R](../../README.md) · [Документация](README.md) · [English](../en/testing.md)

Цель — чтобы у каждого поведения был ровно один тест, который падает, когда это
поведение ломается. Покрытие измеряется, но целью не является: набор тестов,
повторяющий код построчно, только мешает этот код менять.

## Как запускать

```
pytest                  # всё, чему не нужно ни железо, ни сеть
pytest -m live          # остальное: настоящее радио, настоящая сеть, звуковая карта
```

Тесты `live` по умолчанию исключены — так написано в `pyproject.toml`.

## Набор про реестр

`tests/test_registry_contract.py` параметризован по всем зарегистрированным
модулям, поэтому растёт сам. Новый модуль автоматически проверяется на то, что:

- возвращаемый тип соответствует тому, что обещает слот;
- `available()` возвращает булево значение и никогда не бросает исключений;
- объявленные `needs` состоят только из известных имён возможностей;
- модуль переживает пустой вопрос и подставной контекст;
- документация есть на обоих языках, и в ней на месте разделы про зависимости и
  источники.

Из-за этого большинству модулей собственный файл с тестами не нужен. Писать его
стоит только ради той логики, которую контрактный тест увидеть не может.

## Что получает собственный тест

По тесту на каждое поведение, которое действительно может сломаться:

- модуль вопроса детерминирован — один и тот же вопрос даёт один и тот же ключ;
- счёт Да Янь даёт настоящее распределение, в котором старые линии много реже
  молодых; проверяется статистически на многих бросках, с допуском;
- дебиасинг фон Неймана убирает перекос из намеренно перекошенного потока;
- биекция Вавилонской библиотеки ходит в обе стороны: адрес в текст и обратно;
- цепочка журнала сходится, а подделанная запись обнаруживается;
- повторённый вопрос отклоняется;
- штраф за недавнее снижает вес, но не обнуляет его;
- слои настроек перекрывают друг друга в правильном порядке, а при записи в файл
  остаются только отличия от значений по умолчанию;
- определение возможностей возвращает ожидаемые уровни на матрице значений
  `TERM` и `COLORTERM`;
- регулятор усиления доходит до цели, а ограничитель никогда не превышает
  потолок;
- каждый сетевой разборщик справляется со своим записанным ответом.

## Что не получает теста

Тривиальные обёртки, создание дата-классов, таблица строк, внутренности Textual,
точные формулировки сообщений, форматирование вывода. **Если тест ломается от
переименования переменной, такого теста быть не должно.**

## Границы

Тесты не ходят в сеть, не трогают приёмник и не открывают звуковую карту. Для
этого в `tests/conftest.py` лежат подставки:

| Подставка | Что заменяет |
|---|---|
| `stub_context` | настоящий `Context`, с шиной событий в памяти |
| `fake_pcm` | `rtl_fm`, выдаёт синтетические отсчёты |
| `fake_llm` | любого поставщика модели, выдаёт заданный поток токенов |
| `fake_stt` | любого распознавателя, выдаёт заданный текст |
| `tests/fixtures/*.json` | записанные ответы USGS, blockchain, маяка и ADS-B |

Если тесту действительно нужна настоящая вещь, он помечается:

```python
@pytest.mark.live
def test_dongle_actually_tunes(): ...
```

## Тесты интерфейса

Интерфейс водит собственный пилот Textual — `App.run_test()`. Проверяется
поведение и решение о раскладке, но никогда не пиксели: переходы между режимами,
разбор команд, отказ на слишком маленьком терминале, перестроение между 40×12 и
200×50, переопределения раскладки клавиш и переход на более простую анимацию при
бедном наборе глифов.

Снимков экрана нет. Они ломаются от любого постороннего изменения и ничему не
учат.

## Где живут тесты

В том же коммите, что и код, который они покрывают. Шага «написать тесты» в
конце плана нет и не будет.
