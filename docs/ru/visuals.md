# Визуализации

## Как они устроены

Визуализация — это виджет, подписанный на одно событие и больше ни на что. Она не
знает, какой модуль её кормит, а модуль не знает, кто его рисует; между ними
только шина событий.

Из этого следует главное практическое свойство: добавить визуализацию — значит
подписаться на уже существующее событие. Ни один модуль при этом не меняется.

```python
@visual("waterfall", event="spectrum", glyphs="blocks")
class BlockWaterfall(Waterfall):
    ramp = BLOCKS
```

## Уровни глифов

Каждая визуализация объявляет самый бедный терминал, в котором способна
существовать: `ascii`, `box`, `blocks` или `braille`.

Одно и то же имя регистрируется несколько раз с разными уровнями, и реестр отдаёт
самый богатый вариант, который этот терминал вытянет. В современном эмуляторе
водопад рисуется брайлевскими ячейками, в голой консоли — блоками, а если и их
нет, символами `.:-=+*#%@`.

Ни выбирать, ни настраивать это не нужно. Разница между тремя водопадами — одна
строка с набором символов, всё остальное у них общее.

## Что есть сейчас

### waterfall

Подписан на `spectrum`. Новые строки добавляются сверху, старые уходят вниз и
через шестьдесят четыре строки забываются.

Ширина не запоминается нигде: при каждой отрисовке спектр заново раскладывается
по тем колонкам, которые есть сейчас. Поэтому окно можно растянуть посреди
захвата, и захват об этом не узнает.

### idle

Подписан на `tick`. Показывается, когда ничего не происходит.

Это медленно плывущая интерференционная картина, и она честно ничего не значит:
не индикатор выполнения, не уровень сигнала, не визуализация мыслей оракула. Она
нужна только для того, чтобы программа выглядела бодрствующей, а не повисшей.

### reveal

Подписан на `token`. Текст толкования появляется сначала шумом и разрешается по
символам.

Приём взят из `no-more-secrets`, и важна там не анимация, а то, что за ней стоит:
ответ не выпадает готовым, его приходится дождаться.

## Потоки

Захват идёт в рабочем потоке, а виджет можно трогать только из того потока, где
живёт интерфейс. Поэтому события с шины проходят через `call_from_thread`, если
пришли не оттуда, и напрямую, если оттуда.

Модулю об этом знать не нужно: он вызывает `ctx.emit` и продолжает работу.

## Как добавить свою

Подпишитесь на одно из уже существующих событий: `spectrum`, `token`, `stage`,
`audio`, `tick`. Объявите уровень глифов честно — визуализация, требующая брайля,
в консоли просто не будет выбрана, и это правильное поведение, а не поломка.

Геометрию считайте от текущего размера при каждой отрисовке и ничего не
кэшируйте.
