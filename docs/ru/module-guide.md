# Как добавить модуль

Модуль здесь — это один файл, один декоратор и одна функция `run`. К нему
прилагается документация и, как правило, ни одного собственного теста: общий
контрактный набор проверит его сам.

Видов модулей четыре.

| Вид | Пакет | Сигнатура |
|---|---|---|
| Вопрос | `heidr/question/` | `run(ctx, question) -> Key` |
| Мир | `heidr/world/` | `run(ctx, key) -> Material` |
| Толкование | `heidr/reading/` | `run(ctx, question, material) -> Iterator[str]` |
| Визуализация | `heidr/visuals/` | виджет, подписанный на событие |

Тот же самый файл можно положить не в репозиторий, а в
`~/.config/heidr/modules/`. Он попадёт в выбор наравне с остальными, и при этом
проект останется нетронутым.

## Целый источник от начала до конца

Вот `heidr/world/quake.py` полностью — ничего не сокращено.

```python
import requests

from heidr.contracts import Key, Material
from heidr.registry import world

FEED =
"https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_hour.geojson"


def available(ctx) -> bool:
    return ctx.has("net")


@world("quake", needs=("net",), visual="tremor")
def run(ctx, key: Key) -> Material:
    events = requests.get(FEED, timeout=10).json()["features"]
    if not events:
        return Material("", (), "usgs", {})

    event = events[key.seed % len(events)]
    place = event["properties"]["place"]
    magnitude = event["properties"]["mag"]
    lon, lat, depth = event["geometry"]["coordinates"]

    ctx.emit("stage", f"quake {place}")
    return Material(
        text=place,
        numbers=(int(magnitude * 10), int(depth)),
        source="usgs",
        extra={"lat": lat, "lon": lon},
    )
```

Несколько вещей, на которые стоит обратить внимание.

Список `needs` составляется из известных имён: `net`, `sdr`, `stt`, `llm`,
`audio`. Жребий сам пропустит модуль, чьи потребности сейчас не покрыты, так что
проверять это внутри `run` не нужно.

Функция `available()` — это дешёвая проверка, а не полноценная инициализация. Она
не имеет права бросать исключения и не должна висеть дольше доли секунды.

А вот сам модуль бросать исключения вправе, и это ожидаемо. Лента не ответила,
ответ не разобрался, устройство занято другой программой — бросайте: прогон
возьмёт для слота другой модуль, а не остановится. Материал без текста и без
чисел значит ровно то же самое, и обходятся с ним так же.

Толкование, весь смысл которого — промолчать, объявляет это само:
`@reading("mute", silent=True)`. Без этого толкование, не выдавшее ни строки,
считают таким, которому нечего было сказать, и оно уступает место другому.

Параметр `visual` — пожелание, а не требование. Если визуализации с таким именем
нет или терминал её не тянет, вместо неё покажется фоновая анимация, и модуль об
этом даже не узнает.

Единственный способ что-то показать — `ctx.emit`. Никаких `print` в модулях нет.

Наконец, `ctx.settings` — это секция `[modules.quake]` из настроек, уже слитая с
теми значениями по умолчанию, которые модуль объявил сам.

Если модуль проигрывает звук, `ctx.levels` — это собственные громкость, мьют и
выравнивание интерфейса. Их надо передать в `audio.Output`, а не вычитывать
числа из конфигурации: иначе клавиши громкости не достанут до того, что играет.

## Настройки модуля

Значения по умолчанию объявляются прямо на декораторе, а читаются из
`ctx.settings`:

```python
@world("fm_voice", needs=("sdr", "stt"), defaults={"dwell_s": 4, "sweep":
"random"})
def run(ctx, key):
    dwell = ctx.settings["dwell_s"]
```

В редакторе настроек они появятся сами собой — по строке на каждый, с текущими
значениями. Трогать `config.py` при этом не надо ни разу; единственный повод его
открыть — дописать строку в `CHOICES`, если у параметра есть готовый набор
значений и его удобнее переключать клавишей `Enter`, чем набирать.

## Модуль толкования

Толкование отдаёт текст потоком, поэтому оно не возвращает строку, а делает
`yield`:

```python
@reading("cutup")
def run(ctx, question: str, material: Material):
    for line in cut_up(material.text, ctx.settings["max_cut"]):
        yield line
```

Если толкованию нужна языковая модель, она берётся из `ctx.llm`, а токены
передаются наружу как есть, без накопления в буфер.

И самое важное ограничение всего проекта: **модель толкует найденный материал, но
никогда его не выбирает.** Как только модель начинает выбирать, это уже не
программа для поиска совпадений, а генератор текста.

## Визуализация

Визуализация подписывается на событие и честно объявляет самый бедный терминал, в
котором она способна жить:

```python
@visual("waterfall", event="spectrum", glyphs="blocks")
class Waterfall(Widget): ...
```

Значение `glyphs` — одно из `braille`, `blocks`, `box`, `ascii`. Одно и то же имя
можно зарегистрировать несколько раз с разными уровнями, и подходящий вариант
выберется автоматически.

Геометрию нужно пересчитывать от текущего размера при каждой отрисовке. Ширину
кэшировать нельзя: терминал вполне могут растянуть посреди захвата, и захват не
должен этого заметить.

## Прежде чем считать работу законченной

1. Написаны `docs/en/modules/<имя>.md` и `docs/ru/modules/<имя>.md` со всеми пятью
   разделами: что делает, откуда берутся данные, как они обрабатываются, от чего
   зависит, из каких источников заимствовано.
2. Если появилась новая зависимость — она добавлена в таблицы `README.md`, а в
   `pyproject.toml` вынесена отдельным дополнением, когда модуль не основной.
3. Если что-то заимствовано — в файле стоит шапка с автором и лицензией, а в
   `docs/en/credits.md` появилась строка.
4. `pytest` проходит. Контрактный набор уже покрывает новый модуль; свой тест
   пишется только на логику, которую он не видит.
5. Всё это уходит одним коммитом с одной строкой описания: `add quake world
   module`.
