# Поставщики языковых моделей

Толкованию может понадобиться модель, чтобы прочитать найденное. Какая именно
модель и где она работает — вопрос одной строки в настройках.

## Договор

Каждый поставщик — это один класс с одним методом:

```python
def stream(self, messages: list[Message]) -> Iterator[str]
```

Он отдаёт текст по мере поступления. Целиком ответ нигде не накапливается, и
именно поэтому толкование появляется на экране слово за словом, а не выпадает
одним куском в самом конце.

## Что есть в поставке

| `llm.provider` | С чем говорит | Особенности |
|---|---|---|
| `ollama` | с локальным демоном ollama | `POST /api/chat`, построчный JSON |
| `openai_compat` | со всем, что понимает `/v1/chat/completions` | сервер llama.cpp, OpenAI и службы, повторившие его форму |
| `anthropic` | с Anthropic messages API | системная подсказка едет отдельным полем, а не сообщением |

Выбор между сервером llama.cpp и облачной службой — это одна и та же правка:
поменять `base_url` и `model`.

## Настройки

```toml
[llm]
provider = "ollama"
model = "qwen3.5:9B"
base_url = "http://localhost:11434"
api_key_env = "HEIDR_LLM_KEY"
timeout = 120
max_tokens = 1024
think = false
```

Ключ `think` понимает только провайдер ollama. Рассуждающая модель, которой
подсунули стену случайных букв, способна израсходовать весь бюджет вывода на
рассуждение и остановиться с пустым ответом — на экран тогда попадает один лишь
материал. По умолчанию стоит `false`, то есть модель отвечает сразу. Ставьте
`true`, только если и модель, и длина контекста это выдержат.

Обратите внимание: `api_key_env` — это **имя переменной окружения**, а не сам
ключ. Ключи не читаются из файла настроек и не пишутся в него никогда.

## Если поставщика не удалось собрать

Опечатка в имени поставщика или облачная служба без ключа в окружении не
обрушивают обряд на середине. Возможность `llm` просто снимается при опросе
системы, все толкования, которым нужна модель, тихо выходят из жребия, а
`:checkhealth` объясняет, чего не хватает. Оракул продолжает работать теми
толкованиями, которым не нужно ничего.

## Правило, которое старше всего перечисленного

**Модель толкует материал, но никогда его не выбирает.** Толкование передаёт
модели найденное и отдаёт наружу то, что вернулось. Оно не спрашивает у модели,
какую страницу открыть, какую частоту слушать и какую из нескольких находок
предпочесть.

Как только выбор делает модель, ответ становится порождённым, а не найденным, и
программа перестаёт быть оракулом.

## Зависимости

`requests`. Доступ к тому, на что указывает поставщик, — а для ollama и
llama.cpp это localhost.
