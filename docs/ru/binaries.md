# Бинарники и установщики

[HEID//R](../../README.md) · [Документация](README.md) · [English](../en/binaries.md)

Есть два пути, на которых Python не нужен: готовый бинарник, который достаточно
скачать и запустить, и скрипт, который скачивает и сам бинарник, и внешние
программы к нему. Ни то, ни другое не отменяет установку из исходников,
описанную в [установке](install.md), — это короткая дорога для того, кто хочет
попробовать программу сегодня.

В каждом релизе лежит бинарник для каждой системы: Linux, Windows и macOS — и
на Intel, и на Apple silicon. Скрипт приносит бинарник везде, а под Linux
ставит ещё и внешние программы вокруг него.

## Установщик

Linux:

```
curl -fLO https://raw.githubusercontent.com/SilentAutomaton/heidr/master/install.sh
sh install.sh
```

Windows, в PowerShell:

```
Invoke-WebRequest -Uri https://raw.githubusercontent.com/SilentAutomaton/heidr/master/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Скрипт спрашивает, что ставить, и не ставит ничего, чего вы не назвали:

| | Что ставит | Откуда |
|---|---|---|
| 1 | heidr | последний релиз этого репозитория |
| 2 | радиоутилиты | пакетный менеджер системы |
| 3 | ffmpeg и yt-dlp | пакетный менеджер и собственный релиз yt-dlp |
| 4 | whisper.cpp и модель | собственный релиз и Hugging Face |
| 5 | vosk и модель | PyPI и alphacephei.com |
| 6 | ollama и модель | официальный скрипт установки |
| 7 | llama.cpp | собственный релиз |

Обязателен только первый пункт. Всё остальное — это либо источник материала,
либо способ его прочитать, и программа при каждом запуске сама говорит, что из
этого нашла.

Последнее, что делает установщик, — прописывает настройки для установленного:
`stt.provider`, `stt.model_path`, `llm.provider`, — и запускает
`heidr --self-check`. Так последним на экране оказывается заключение самой
программы, а не установщика.

Прочитайте скрипт перед запуском. Это один файл, он короткий, и он лежит в этом
же репозитории.

## Чего установщик делать не станет

**RTL-SDR под Windows.** В Windows нет драйвера, с которым умеют работать
программы `rtl_*`. Установщик говорит об этом прямо и показывает путь через
WSL2, вместо того чтобы упасть на половине дела.

**vosk вместе с бинарником.** vosk — это модуль Python, который программа
импортирует. У готового бинарника внутри свой интерпретатор, и увидеть
что-либо поставленное через `pip` он не может, так что vosk работает только с
установкой из исходников. whisper.cpp — отдельная программа, которую heidr
запускает как подпроцесс, и она годится в обоих случаях. Установщик
предупреждает об этом заранее.

**Подпись.** Ни один бинарник не подписан. Windows SmartScreen и Gatekeeper в
macOS скажут об этом перед первым запуском, а у скачанного через браузер файла
стоит карантинная метка: `xattr -d com.apple.quarantine heidr-macos-*`
снимает её.

**Внешние программы на macOS.** Там скрипт приносит только бинарник.
Приёмник, распознаватель речи и остальное ставятся своими руками; программа
при каждом запуске сама говорит, что из них нашла.

## Один бинарник, без установщика

Бинарники называются `heidr-linux-x86_64`, `heidr-windows-x86_64.exe`,
`heidr-macos-x86_64` и `heidr-macos-arm64`, а рядом с ними лежит `SHA256SUMS`.
Взять их можно и без скрипта, Linux:

```
curl -fLO https://github.com/SilentAutomaton/heidr/releases/latest/download/heidr-linux-x86_64
chmod +x heidr-linux-x86_64
./heidr-linux-x86_64 --self-check
```

Тот же адрес с другим именем файла приносит бинарник для Windows или macOS;
на macOS после скачивания нужен `chmod +x`.

Бинарник для Linux идёт на любом дистрибутиве с glibc 2.31 и новее — Ubuntu
20.04, Debian 11 и всё, что вышло позже. Python и все зависимости лежат внутри
него, ставить рядом ничего не надо.

Чего внутри нет — так это внешних программ. `rtl_fm`, `ffmpeg`, `whisper-cli` и
ollama запускаются подпроцессами или опрашиваются по сокету, поэтому их ищут в
PATH при запуске — ровно так же, как при обычной установке. Отсутствие одной из
них убирает источники, которым она нужна, и больше ничего. Единственное, чему
внутри бинарника всё-таки нужна системная библиотека, — это звук: `sounddevice`
ищет `libportaudio2`, и без неё оракул говорит беззвучно.

## Настройки из командной строки

Установщик настраивает программу тем же ключом, которым можете воспользоваться
и вы:

```
heidr --set stt.provider=whisper_cpp --set stt.model_path=~/.local/share/heidr/models/ggml-large-v3-turbo-q5_0.bin
```

Каждый `--set` принимает одно имя и одно значение. Значение читается по виду:
`true` и `false` становятся переключателями, цифры — числами, всё остальное
остаётся текстом. Имя, которого в настройках нет, будет отвергнуто, а не
записано. Те же настройки правятся внутри программы командой `:set`, о которой
написано в [настройках и модулях](settings-editor.md).

## Собрать самому

```
sh tools/build_release.sh
```

Бинарники для Windows и macOS собираются там, где работают. PyInstaller пакует
интерпретатор и готовые wheel'ы той архитектуры, под которой запущен сам, —
поэтому бинарнику для Windows нужна Windows, бинарнику для macOS нужен Mac, а
кросс-сборки он не умеет совсем. Workflow `.github/workflows/build-binaries.yml`
собирает Linux, Windows и macOS на Apple silicon через GitHub Actions и кладёт
бинарники в артефакты прогона — запускается он из вкладки Actions с тегом
нужного релиза. Intel macOS — единственная цель, которой нет среди
бесплатных раннеров, поэтому её бинарник собирается на настоящем Mac вручную:
venv с `pip install pyinstaller '.[audio,effects]'`, затем
`pyinstaller heidr.spec` — ровно как в README описано для Linux.

Результат оказывается в `dist/`, рядом с ним ложится `SHA256SUMS`.

## Проверка

```
heidr --self-check
```

По строке на каждую возможность, и для каждой отсутствующей — что поставить.
Как читать этот отчёт, написано в [проверке](checkhealth.md).
