# chain — источник

[HEID//R](../../../README.md) · [Документация](../README.md) · [Модули](../README.md#модули) · [English](../../en/modules/chain.md)

## Что делает

Читает свежий биткойн-блок: корень Меркла даёт числа, а надписи, за которые люди
заплатили, чтобы вписать их в блок, — текст.

## Откуда берутся данные

Из двух точек входа blockchain.info:

```
https://blockchain.info/latestblock
https://blockchain.info/rawblock/{hash}
```

Второй ответ большой — это целый блок со всеми транзакциями, — поэтому тайм-аут
по умолчанию щедрый.

## Как обрабатывается

1. Загружается хэш последнего блока, потом сам блок.
2. Берётся **корень Меркла**, а не хэш блока. Сложность майнинга загоняет в хэш
   блока всё более длинную цепочку ведущих нулей и год за годом вымывает из него
   энтропию; у корня Меркла такого перекоса нет.
3. Корень режется на четыре куска по восемь символов и читается как
   шестнадцатеричное. Это и есть числа материала.
4. Каждый выход транзакции, чей скрипт начинается с `6a` — это код операции
   `OP_RETURN`, — декодируется как UTF-8 и очищается от непечатаемых символов. То,
   что уцелело, становится текстом материала.

`OP_RETURN` — это место, куда люди намеренно вписывают в цепочку что-нибудь:
имена, даты, метки протоколов, шутки, поминальные записи. За каждую из них
кто-то заплатил комиссию, и ни одна не была адресована вам.

## Настройки

| Ключ | По умолчанию | Что значит |
|---|---|---|
| `timeout` | 15 | Сколько секунд ждать, на каждый запрос |
| `messages` | 5 | Сколько записей `OP_RETURN` оставить |

## Зависимости

`requests`. Доступ к сети.
