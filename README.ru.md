<p align="center"><a href="README.md">In English</a></p>

Модальная терминальная программа, которая отвечает на вопрос не сочинённым
текстом, а найденным. Материал берётся из радиошума, из самолёта, проходящего
над головой, из последнего землетрясения, из страницы Вавилонской библиотеки.
Языковая модель может истолковать найденное, но выбирать его ей не дают, и
совпадение программа за доказательство чего-либо не выдаёт.

Название — от Хейд, вёльвы из «Прорицания вёльвы»: её трижды сжигали и трижды
она рождалась заново, и она ходила по дворам, рассказывая людям, что их ждёт.
Имя задаёт оформление; внутри при этом обычная программа.

> Документация: [русская](docs/ru/README.md) · [английская](docs/en/README.md)

## В прогоне три слота

```
вопрос ──> [модуль вопроса] ──> Key ──> [источник] ──> Material ──> [толкование] ──> ответ
```

Перед каждым прогоном для каждого слота случайно выбирается один модуль, поэтому
цепочка всякий раз другая. Семя для выбора берётся из измерений, а не из
псевдослучайного генератора: радиошум, публичный маяк случайности, корень Меркла
свежего блока. Десять модулей вопроса, четырнадцать источников и шесть толкований
дают 840 различных цепочек. В интерфейсе цепочка называется «обрядом», и в коде
тоже (`Rite`).

Журнал записывает вопрос до того, как что-либо загружено, и каждая запись
скреплена печатью с предыдущей. Вопрос, на который был получен ответ, нельзя
задать повторно до следующего дня; вопрос, оставшийся без ответа, не стоит
ничего.

Модулю сегодня может быть нечего ответить: лента недоступна, в ответе нет
нужного поля, модель вернула пустую строку. Прогон от этого не обрывается — слот
берёт следующий модуль, а панель сообщает, кто кому уступил.

## Модули

Обязательных здесь нет. Модуль, чьи потребности не покрыты, в выборе не
участвует, а `:checkhealth` объясняет, чего не хватает.

## Что нужно каждой возможности

| Возможность | Нужно | Без неё |
|---|---|---|
| `net` | Работающая сеть | Три источника выпадают из выбора |
| `sdr` | Донгл RTL-SDR и программы `rtl_sdr`, `rtl_fm`, `rtl_power`; для двух источников `rtl_433` и `dump1090`; для одного `noaa-apt` | Девять источников выпадают из выбора |
| `stt` | [vosk](https://github.com/alphacep/vosk-api) или собранный [whisper.cpp](https://github.com/ggml-org/whisper.cpp) с моделью | Нет голосового ввода и расшифровки эфира |
| `llm` | Доступная ollama, сервер llama.cpp или ключ к облачной службе | Три модуля выпадают из выбора |
| `audio` | `sounddevice` и устройство вывода | Программа работает молча |

Без всего перечисленного цепочка `gematria//babel//iching` всё равно работает и
ничего не просит у внешнего мира.

## Установка

Python 3.11 или новее и терминал этого века. Что нужно каждой системе и что где
не работает, написано в [заметках об установке](docs/ru/install.md).

### Linux

```
pip install -e '.[audio]'
heidr
```

Здесь работает всё: радио, звук, распознавание, локальные модели. Приёмнику
нужен пакет `rtl-sdr` из репозитория дистрибутива.

### macOS

То же самое, нативно. Эмулировать ничего не требуется.

```
brew install rtl-sdr ollama
pip install -e '.[audio]'
```

### Windows

Понадобится Windows Terminal, а не старый хост консоли. Работает всё, кроме
приёмника: `numpy` и `sounddevice` ставятся готовыми колёсами, у ollama есть
своя сборка, а управляющую последовательность, которой копирует `y`, Windows
Terminal понимает.

```
py -m pip install -e ".[audio]"
py -m heidr
```

Исключение — донгл. До драйвера Linux устройство USB добирается только через
WSL2, куда его пробрасывает [usbipd-win](https://github.com/dorssel/usbipd-win);
внутри WSL2 радио ведёт себя так же, как на Linux.

Дополнения на любой системе: `pip install -e '.[audio,vosk,effects]'`

### Одним файлом

Есть рецепт для PyInstaller — на случай, когда ставить в систему ничего нельзя:

```
python -m venv build-env
build-env/bin/pip install pyinstaller '.[audio,effects]'
build-env/bin/pyinstaller heidr.spec
```

`dist/heidr` получается единственным исполняемым файлом мегабайт на тридцать
семь, внутри которого лежат и Python, и все зависимости. Внешние программы
остаются внешними: `rtl_fm`, `whisper-cli` и прочие запускаются процессами, то
есть либо находятся на PATH, либо соответствующая возможность просто
отсутствует — ровно как при обычной установке.

## Настройка

```
cp config.example.toml ~/.config/heidr/config.toml
cp keymap.example.toml ~/.config/heidr/keymap.toml
```

Ключи к облачным службам читаются только из переменных окружения и в файл
настроек не попадают никогда. Образец — в `.env.example`.

## Как пользоваться

Программа открывается меню, и у каждой строки написаны команда и клавиша,
делающие одно и то же: управление читается с экрана, а не заучивается по
инструкции. Двигают стрелки или `j` и `k`, `Enter` выбирает, `Esc` возвращает на
уровень назад, мышь работает, а `ui.splash=false` убирает знак над списком.

Клавиши взяты у vim, и рядом с каждой стоит вторая, известная всем: `F1` —
справка, `Home` и `End` — концы списка, `Insert` — начать набор, `Ctrl-S` —
сохранить, `Ctrl-Z` — отменить, `Ctrl-C` — остановить или выйти.

Для привыкших к vim: `i a A I o O` открывают поле вопроса, `gg` и `G` прыгают в
начало и конец, `Ctrl-D` и `Ctrl-U` листают на полэкрана, `{` и `}` ходят по
группам настроек, `/` ищет, а `n` и `N` перебирают найденное, `y` копирует, `u`
отменяет изменение настройки, `ZZ` сохраняет и выходит. Вся раскладка и пять
мест, где эта программа с vim расходится, собраны в
[справочнике клавиш](docs/ru/keys.md).

Режимы устроены как в neovim. `:ask` задаёт вопрос, `Ctrl-V` в режиме вставки
позволяет его продиктовать. Стрелки вверх и вниз, а также `Ctrl-P` и `Ctrl-N`,
возвращают набранное раньше; команды и вопросы хранятся в двух файлах в
`~/.local/share/heidr` и листаются порознь. Команда `:modules` показывает, что
доступно и почему, `:settings` правит любой параметр, `:ledger` открывает
прошлые прогоны, `:checkhealth` объясняет, чего не хватает, `:w` сохраняет, `:q`
выходит.

Цепочку можно назвать вместо того, чтобы полагаться на случай:
`:draw rarest//babel//iching`, где `*` в любом слоте оставляет выбор случайности.
То же самое собирается из меню по слоту за раз. Названная цепочка помечается в
журнале как `(chosen)` и правилу «один ответ в сутки» не подчиняется: задать один
вопрос нескольким цепочкам — это опыт, и пометка отделяет его от обычного
прогона.

У каждой стадии своя анимация, и добавляется она тоже одним файлом:
[руководство по анимациям](docs/ru/animations.md).

Модуль добавляется одним файлом: [руководство по модулям](docs/ru/module-guide.md).
Достаточно положить его в `~/.config/heidr/modules/`, и ядро при этом не
правится.
